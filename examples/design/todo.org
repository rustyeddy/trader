#+TITLE: Trader Design — Prioritized TODOs
#+STARTUP: overview

* Ground Rules
- Design APIs first; keep everything in =examples/design= private
  until settled.
- After EACH task, =make check && make run= must succeed with small
  deterministic synthetic data.
- Prefer concrete types and one readable call path; no new framework
  or interface without a demonstrated need.
- Preserve causal backtest timing; distinguish simulated broker
  rejection from infrastructure failure.
- Do not start retrofitting production packages until the milestone
  below is reviewed.

* P0 — Core Contracts (next iteration)

** TODO 1. Define Order semantics and errors
An order carries one request through its whole life: the strategy asks, the
account sizes (or rejects), the broker fills (or rejects), and the trader
records the result. See =order-tests.org= for the scenarios.
- [X] Decide what an order expresses: a small action (open/add/reduce/close)
  plus direction for opens, not a broker order and not a position target.
- [ ] Decide whether a strategy can query *read-only* current positions;
  separate signal generation from portfolio/account sizing and execution.
  (Optional snapshot function at construction; not built yet.)
- [X] Specify instrument, direction, close, stop, and size without requiring
  account knowledge: the strategy sets instrument, action, direction (open),
  price and stop (open); the account sets units. Target is not required.
- [ ] Decide whether signal quality (A/B/C, score) is optional metadata that
  risk/sizing *may* use, not a hidden sizing rule.
- [X] Define no-op/no signal, validation, and rejection semantics: a nil
  =*order= is no signal, =order.validate()= rejects malformed orders, and
  expected rejections are sentinel errors.
- [X] Demonstrate long entry/exit, short entry/exit, reversal and no-op
  (=emax=: a flip is a close, then the opposite open on the next bar).
- [X] Keep one order per bar initially.
- [ ] Test whether multiple orders per bar are truly needed (multi-symbol
  strategies, TODO 4).
- [X] Acceptance: no stringly typed ambiguous =side= values; direction and
  action are separate typed enums.

- Explore shared bar consumption without forcing non-trading outputs into

* P1 — Multi-Instrument Market Data and Shared Runner

** TODO 4. Make bars self-contained and decide multi-symbol observation semantics
- Include observed timestamp, instrument identity, OHLCV and price basis
  (bid/ask/trade; spread provenance as needed) in an observation.
  (=bar= has instrument, time and OHLCV; the price basis is still open.)
- Compare =OnBar(bar)= versus =OnBars(frame)= with a single- and two-symbol
  example. Decide whether frame contains only fresh bars or carried values.
- Define deterministic time ordering, simultaneous timestamps, missing
  symbols, sparse instruments and no look-ahead; never silently synthesize bars.
- Consider a multi-symbol strategy that produces 0, 1, or several orders.
- Acceptance: two synthetic datasets interleave correctly, with an
  incomplete/missing observation test.

** TODO 5. Extract or rename the shared data runner only if it simplifies
- Try one small =run(ctx, observations, onBar, handler)= loop for historical
  trading, live trading and trade-signal studies.
- Do not force indicator-only studies/scanners to return =*order=.
- Backtest retains simulated clock, pending-order eligibility, fill sequencing
  and results; common loop must not cause same-bar look-ahead.
- Prefer a concrete function over a =DataRunner= interface until there is a
  real substitution need.
- Acceptance: identical test strategy logic runs in historical and
  live-like synthetic scenarios.

** TODO 6. Establish Query / Dataset / Load API contracts
- Define query: instruments, interval, [start,end), provider/basis and
  explicit coverage/gap policy.
- Compare =dataset, err := marketdata.Load(ctx, query)= followed by
  =dataset.Bars(ctx)= with a stateful =md.Load(); md.Bars()= API.
- Keep =iter.Seq2[Observation, error]= as the current lazy baseline;
  assess slice and channel alternatives only against concrete use cases.
- Dataset hides multi-file assembly, time ordering, caching and resource
  lifetime; define ownership/closing only where genuinely needed.
- Acceptance: an in-memory synthetic dataset satisfies the selected API;
  disk/network loading not required yet.

* P2 — Follow-on Implementation (after milestone)
** TODO Account / portfolio / risk
- Account facts, open positions, balance/equity, margin available,
  position sizing, and portfolio risk policies; wire simple synthetic fills.
- [X] Instrument registry (=instrument=, keyed by symbol) and fixed-point
  =rate= (=rateScale= 1_000_000).
- [X] Open orders sized from =riskPct= and the strategy's stop, limited by the
  margin available (50:1 for EURUSD): units are the smaller of the risk limit
  and the margin limit, rounded to the unit step and capped at the maximum.
  A margin shortfall shrinks the trade; the order is rejected only when the
  result is below the instrument's minimum.
- [ ] Positions in =account.positions=, created and updated when a fill comes
  back (netting: one position per instrument).
- [ ] =close= resolves to the real position size (units 0 means "whole
  position" today); add/reduce sizing once their size type is defined.
- [ ] Margin available accounts for margin already used; equity includes
  unrealized P/L (needs mark prices).
- [ ] Quote-to-account currency conversion (account currency is assumed to be
  the quote currency today).
