* Purpose

This document version-controls Trader's milestone plan so that the issue
breakdown lives beside the architecture it implements.

The canonical architecture document
=docs/arch/trader-framework-architecture.org= (Appendix D) defines the
milestones.  This document restates them and records the issue
breakdown per milestone.  Where the two disagree, the architecture
document governs.

GitHub remains the working tracker.  This file is the durable record of
what each milestone is *for*, so that a closed issue whose deliverable
never landed can be detected.

* Milestones

| ID | Milestone                                 | Usable outcome                                                                    |
|----+-------------------------------------------+-----------------------------------------------------------------------------------|
| M0 | Repository Foundation and Guardrails      | Repository, CI, docs, ADRs, dependency rules, and legacy transplant policy         |
| M1 | Domain Foundation and Test Kit            | Exact values, identity, instruments, time, orders, snapshots, and testing helpers  |
| M2 | Market Data Vertical Slice                | Acquire, normalize, validate, store, query, resample, and report coverage          |
| M3 | Broker Simulation and Account State       | Broker port, simulated execution, account projection, portfolio, reconciliation    |
| M4 | Strategy-to-Execution Pipeline            | Strategy descriptors, intents, planner, risk, execution, correlated journal records |
| M5 | Deterministic Backtesting and Org Reports | Repeatable backtest, run manifest, metrics, journal, CLI, and Org output           |
| M6 | OANDA Paper Trading and Live Safety       | Real adapter, reconciliation, guards, recovery, paper-default live runner          |
| M7 | Scanner and Operator Workflow             | Watch/hot/tradeable state machine, ranking, alerts, reports, operator CLI/API      |
| M8 | Research and External Strategy Extensions | Sweeps, walk-forward, comparison validation, external strategy protocol            |

Real-money trading is deliberately not a milestone.  It is a release
gate after M6 has operated safely in paper mode for a sustained period
and reconciliation, recovery, and guard behavior have been reviewed.

* M0: Repository Foundation and Guardrails

M0 establishes the rules and tooling that constrain every later
milestone.  Its deliverables are documentation and CI, not domain code.
M0 deliberately produces no packages: an empty speculative package tree
would predetermine boundaries before M1 has a real consumer.

** Exit Criteria

M0 may close when all of the following hold:

- Every deliverable above exists on the default branch.  A closed issue
  whose file is absent does not count.
- =README.md=, the architecture document, the ADR registry, the package
  boundaries document, and =CONTRIBUTING.org= do not contradict one
  another.
- Every repository-relative documentation link resolves.
- CI mirrors the =Makefile= and passes from a clean checkout.
- No speculative empty package tree exists.
- No live-trading behavior is present or reachable by default.

* M1 and Later

Issue breakdowns for M1 through M8 are recorded here as each milestone
is planned.  They are intentionally absent until the preceding
milestone's exit criteria are met, so that planning reflects what was
actually learned rather than what was assumed.

The architecture document's "Recommended Development Sequence" section
describes the intended content of each milestone and is the input to
that planning.
