* Legacy Reference Survey (=../trader-first-try=)

ADR-013 governs how this code is used: define the boundary and contract
first, write the contract or behavior test, *then* inspect the legacy
implementation, copy only the smallest useful portion, and rewrite it to
obey the new dependency direction and vocabulary.  The new module never
imports the legacy module.

The legacy market-data code is roughly 4,500 lines across =market/=,
=datamanager/=, and =brokers/oanda/=.  Much of it encodes expensive
lessons that would be costly to rediscover.

** Lessons the legacy code already paid for

1. *Never reconstruct a bar's timestamp from its array position.*
   =market/candle.go='s doc comment records legacy issue #179: deriving a
   candle's time from =Start + idx*step= silently mislabeled D1/H4 candles
   across a DST transition.  The observed open time must be stored
   verbatim.  This directly constrains M2-02's =Bar=.
2. *Fixed-stride aggregation is wrong for session-aligned intervals.*
   =candle_agg.go= special-cases =dailyAligned= timeframes and walks real
   day boundaries, because the calendar day containing a DST transition is
   23 or 25 wall-clock hours.  M2-09 must do the same through =Calendar=
   rather than duration arithmetic — ADR-012's =FXCalendar= already
   computes rollovers the correct way.
3. *A gap is not a gap if the market was closed.*  =classifyGap= already
   separates weekend from suspicious; M2-10 should generalize this to
   "consult the =Calendar=" rather than hard-code weekday logic.
4. *Canonical data should be checkable against the raw archive.*
   =compareRawOandaMonth= cross-checks stored canonical candles against
   preserved raw provider rows.  That is the M2-01 "preserve raw
   observations" decision paying off, and a strong M2-08 test.
5. *Holiday data exists and is real.*  =isMajorForexHolidayClosed= encodes
   Jan 1, Dec 25, Dec 26, and the Dec 24/31 early closes.  ADR-012 ships
   =FXCalendarParams.Holidays= with no data; this is the donor.
6. *Providers come in two shapes.*  =datamanager/provider.go= splits
   =Provider= (downloads raw files, Trader aggregates locally — Dukascopy)
   from =CandleProvider= (returns finished candles — OANDA REST).  M2-05
   must confirm =HistoricalSource= accommodates both without forcing one
   to pretend to be the other.
7. *Raw bid+ask preservation was already found necessary.*
   =RawCandleRow= keeps provider-native bid *and* ask OHLC alongside the
   canonical bid-only candle.  M2-01 must decide whether canonical =Bar=
   is bid-only, mid, or carries both — the legacy answer was bid-only
   canonical plus a raw archive.
8. *Spread and tick count belong on an FX bar.*  Legacy =Candle= carries
   =AvgSpread=, =MaxSpread=, and =Ticks=.  M2-02 should decide
   deliberately whether =Bar= carries them, rather than discovering the
   need in M5 when the backtest fill model wants a spread.
9. *=market.CandleIterator= already converged on Trader's reader shape*
   (=Next=/=Err=/=Close=), which corroborates M2-03's =Reader[T]= — but
   it lacks a =context.Context=, which is exactly the M2-03 improvement.

** What must *not* be carried forward

These are the legacy structures that conflict with accepted decisions.
Copying an algorithm is encouraged; copying its shape is not.

- =getStore()= / =store_globals.go= — a package-level store singleton.
  Violates the prohibition on global mutable state; the store is
  constructor-injected.
- =init()=-time provider registration (=registry.go=).  Violates
  package-boundaries rule 9 and determinism; providers are composed at a
  composition root.
- =string= instruments and =string= timeframes throughout.  M1 already has
  =instrument.ID=/=Listing= (ADR-003, ADR-016) and typed
  =marketdata.Interval= (ADR-012).  Provider symbol strings resolve
  through =instrument.Resolver= and never become identity.
- =float64= in =RawCandleRow=, and =parseFloat= discarding its error.  M2
  uses =num.Price=/=num.Quantity= at the canonical boundary (ADR-004).
- The dense-slot-array-plus-=Valid=-bitset representation.  It is an
  efficient *storage* layout that leaked into the domain type; in M2 it
  may live inside a store adapter, never in the public =Bar= vocabulary.
- Hard-coded =/srv/trading/data= paths and the package-level =log= import.
  Configuration and logging arrive through =config= and =logging= at the
  composition root.
- =market.Candle='s =IsZero=-based "genuinely timeless candle" convention.
  M2-02 gives zero values an explicitly invalid meaning instead.
- =CandleValidationIssue='s JSON tags on a domain type.  Package-boundaries
  rule 7: an encoding concern does not shape the domain vocabulary.

* Issue Detail

** M2-01 Decide canonical market-data model, storage, and adjustment scope

*** Objective

Settle the market-data questions the architecture document leaves open,
before any type is written, and record the outcome as an ADR (next free
number, ADR-020).

*** Questions this issue must answer

1. Does canonical storage hold raw quotes/trades *plus* derived bars, or
   bars only for the first release?  (Architecture: "Market Data" open
   questions.)
2. How are adjusted equity data and corporate actions represented — and
   is that in scope at all for M2, given ADR-003's exchange+ticker
   equity identity is already flagged provisional?
3. How are continuous futures series built and identified, given
   ADR-003 already reserves =KindContinuousSeries=?
4. Is a file format (CSV now, Parquet later) a local implementation
   detail behind =Sink=/=HistoricalSource=, or does it become a shared
   external contract?
5. Which timeframes and session-alignment rules are required for M2's
   one data path?  (Recommendation: FX only, =M1=/=H1=/=H4=/=D1=/=W1=,
   =FXCalendar= — the exact set ADR-012 already implements.)
6. Are raw provider observations preserved immutably, with adjustment
   and derivation selected at query time?  (Architecture says yes;
   this issue makes it a decision rather than an aspiration.)
7. Is a canonical FX =Bar= bid-only, mid, or bid+ask?  Legacy Trader
   settled on bid-only canonical plus a preserved raw bid+ask archive
   (=datamanager/provider.go=, =RawCandleRow=); M2 should adopt or
   reject that deliberately, because it determines what M5's fill model
   can compute without re-fetching.

*** Recommended answers (for review)

- *Bars only* as the canonical stored record for M2; quotes and trades
  get canonical *types* (M2-02) so live/tick work in M6 is additive, but
  no tick store is built now.
- *Corporate actions and adjusted equity deferred* out of M2.
  =AdjustmentMode= is defined (M2-04) with only =Raw= implemented;
  other modes return an unsupported-capability error rather than a
  silently wrong series.
- *Continuous futures deferred* out of M2, consistent with ADR-003.
- *File format is an implementation detail* behind the ports.  CSV
  first, per the requirements document; nothing outside the adapter may
  name a format.
- *Raw preserved, derivation at query time*, recorded in coverage /
  run manifest — never a destructive overwrite of source data.  Legacy
  =compareRawOandaMonth= shows the payoff: canonical data can be
  audited against the archive it came from.
- *Bid-only canonical bars, plus average and maximum spread carried on
  the bar*, following the legacy =Candle=.  Spread is what M5's fill
  model needs, and recomputing it later requires re-fetching raw data.

*** Non-goals

- Writing any code.

*** Acceptance criteria

- [ ] ADR added to =docs/arch/adr-decisions.org= with status =Accepted=.
- [ ] Each of the six questions above has an explicit answer or an
      explicit, reasoned deferral.
- [ ] The decision index table is updated.
- [ ] The architecture document's "Market Data" open questions are
      updated to point at the ADR.

*** Dependencies

None.  Blocks every other M2 issue.

** M2-02 Define canonical market-data event types

*** Objective

Add the canonical observation types the =marketdata= package promises:
=Bar=, =Quote=, =Trade=, =BookUpdate= (type only, if in scope), and the
provenance and quality metadata every record carries.

*** Scope

- =Bar=: OHLC as =num.Price=, volume as =num.Quantity=, =Interval=, and
  a =TimeRange= (half-open, per ADR-012) rather than a bare timestamp.
- =Quote=: bid/ask prices and sizes, event time, source.
- =Trade=: price, size, event time, source — named to avoid collision
  with =order.Trade='s reporting meaning (Appendix C warns about this;
  =marketdata.Trade= is a market print, and its doc comment must say so).
- Provenance carried on every record: listing identity, source provider,
  event time, observed time, sequence number when available,
  raw/adjusted/synthetic status, revision.
- =QualityFlag= / =QualityWarning= vocabulary, with a reserved zero value
  for "unrecognized", matching the =Unknown=-value pattern ADR-012 and
  ADR-017 already established.
- Constructors that validate: OHLC ordering (=low <= open,close <= high=),
  non-negative volume, price divisibility by =Spec.TickSize=, non-zero
  listing, non-zero times, =TimeRange= consistent with =Interval=.

*** Non-goals

- Acquiring, storing, validating a *series*, or resampling.
- Corporate-action or adjustment computation.

*** Acceptance criteria

- [ ] =Bar=, =Quote=, =Trade= exist with exact numeric types throughout.
- [ ] Every record preserves provenance and can report whether it is raw.
- [ ] Constructors reject each invariant violation with classifiable
      sentinel errors.
- [ ] Zero values are documented as invalid, not silently meaningful.
- [ ] =marketdata.Trade= versus =order.Trade= ambiguity is addressed in
      doc comments.
- [ ] Tests cover boundary and failure modes; =make check= passes.

*** Legacy reference

=market/candle.go=, =market/tick.go=.  Adopt: the authoritative stored
=Timestamp= (legacy #179), =AvgSpread=/=MaxSpread=/=Ticks=, =BA.Mid='s
half-up rounding, and =Validate='s OHLC-shape rule that permits
=High == Low=.  Reject: the =IsZero= "timeless candle" convention and
=string= instrument fields.

*** Dependencies

M2-01.  Uses M1-04, M1-07, M1-09.

** M2-03 Define typed reader and streaming ownership contract

*** Objective

Provide the single streaming abstraction the architecture document
specifies — =Reader[T]= with =Next(ctx)= returning =io.EOF= at
completion, plus =Close()= — and document concurrency ownership.

*** Scope

- =Reader[T any]= interface.
- Helper constructors: reader over a slice, reader over a channel,
  reader that concatenates, reader that maps/filters (only those with a
  real consumer in M2 — no speculative combinator library).
- Documented answers, per the architecture's "Concurrency Ownership and
  Backpressure" section, for every reader: does it start goroutines,
  which context owns them, who closes, is it safe for concurrent use,
  what happens to a slow consumer, and what may be coalesced or dropped.
- Explicit rule that completed bars are never silently dropped; only
  high-frequency quote streams may coalesce, and only when the consumer
  opts in.

*** Non-goals

- A channel-first public API.  Channels may appear as helpers, never as
  the only abstraction.

*** Acceptance criteria

- [ ] =Reader[T]= exists and is used by every streaming M2 API.
- [ ] Cancellation via context is tested, including mid-stream.
- [ ] =Close= is idempotent and releases resources; tested.
- [ ] Race detector passes on all reader tests.
- [ ] Concurrency ownership is documented per constructor.

*** Legacy reference

=datamanager/data_iterator.go= and =market.CandleIterator=.  The legacy
=Next=/=Err=/=Close= shape, and its =funcIterator=, ranged, and chained
constructors, are close to =Reader[T]= already and show which
combinators had real consumers.  The gap to close is =context.Context=:
legacy iterators cannot be cancelled.

*** Dependencies

M2-01.

** M2-04 Define query, adjustment, and fetch-policy vocabulary

*** Objective

Define the request types that make a data query reproducible.

*** Scope

- =BarQuery=, =QuoteQuery=, =CoverageQuery= with half-open =[Start, End)=
  ranges, matching ADR-012's =TimeRange= convention.
- =AdjustmentMode= (=Raw=, =SplitAdjusted=, =TotalReturnAdjusted=,
  =BackAdjusted=), with only =Raw= supported in M2 per M2-01; the others
  must return an unsupported-capability error.
- =FetchPolicy= (=LocalOnly=, =FetchMissing=, =ExactManifest=) so a
  reproducible backtest can require that missing data *fails the run*
  rather than silently changing its input set.
- Query validation: non-empty instruments, valid interval, ordered range.

*** Non-goals

- Executing a query.  Ports land in M2-05.

*** Acceptance criteria

- [ ] Boundary inclusivity is documented and tested at both ends.
- [ ] An unsupported =AdjustmentMode= is a classifiable error, never a
      silent fallback to =Raw=.
- [ ] =LocalOnly= is proven, by test, to fail rather than fetch.
- [ ] Query values are comparable/hashable enough to key a manifest.

*** Dependencies

M2-02, M2-03.

** M2-05 Define historical source, live feed, sink, and coverage ports

*** Objective

Define the narrow extension contracts adapters implement.

*** Scope

- =HistoricalSource=: =Bars=, =Quotes=, =Coverage=.
- =LiveFeed=: =Subscribe= returning a =Reader[Event]=.
- =Sink= (persistence): =WriteBars=, =WriteQuotes=.  Per
  package-boundaries rule 12, evaluate whether =Sink= stays public or
  starts =internal/= until a user genuinely implements it — the
  architecture document explicitly allows either.
- =CoverageCatalog=: =Coverage=, =Gap=, =QualityWarning= reporting.
- =Event= convenience union with an explicit, non-ambiguous event kind.
- Adapter capability reporting: which intervals, adjustment modes, and
  history depth a source actually supports.

*** Non-goals

- Any implementation.  M2-06 onward.

*** Acceptance criteria

- [ ] Each port is small enough that one adapter can implement it
      without stubbing unrelated methods.
- [ ] Every method documents cancellation, ownership, and error
      classification.
- [ ] No vendor SDK, file-format, or database type appears in any
      signature (package-boundaries rules 1 and 7).
- [ ] Compile-time assertions that the M2-06 in-memory implementation
      satisfies each port.
- [ ] Both legacy provider shapes (raw-file download and finished-candle
      API) fit the ports without one impersonating the other.

*** Legacy reference

=datamanager/provider.go= — the =Provider= versus =CandleProvider= split,
and =ProviderStore= as a deliberately narrow store slice handed to
provider implementations.  Reject the =ForProviders()= global accessor
backing it.

*** Dependencies

M2-02, M2-03, M2-04.

** M2-06 Implement in-memory canonical store and historical source

*** Objective

Provide the reference implementation of the ports — the one that proves
the contracts are usable and that every later test can depend on.

*** Scope

- In-memory store implementing =Sink=, =HistoricalSource=, and
  =CoverageCatalog=.
- Deterministic ordering, deduplication by (listing, interval, start),
  and last-write-wins revision handling.
- Safe for concurrent use, or documented as not; tested under =-race=.

*** Acceptance criteria

- [ ] Round-trip: write bars, query them back identically.
- [ ] Half-open boundaries honored exactly at both ends.
- [ ] Duplicate and out-of-order writes handled per M2-01's decision.
- [ ] Passes the M2-13 contract suite once that lands.

*** Dependencies

M2-05.

** M2-07 Implement provider adaptation and a CSV provider adapter

*** Objective

Build the first of the two normalization stages the architecture
document requires: *adaptation* of provider-native records into
canonical records, kept strictly separate from *validation* (M2-08).

*** Scope

- Adaptation interface/shape: provider-native row → canonical =Bar=,
  with provenance populated (source, observed time, revision, raw).
- A CSV provider adapter reading legacy Trader fixtures, per ADR-013's
  controlled-transplant rule: capture behavior with a fixture test
  first, copy only the smallest useful portion, rewrite to the new
  vocabulary, never import the legacy module.
- Symbol → listing resolution through =instrument.Resolver= (ADR-016),
  so provider symbol spellings never become identity.
- Timezone/parse failures reported as classifiable errors with the
  offending row preserved.

*** Non-goals

- Validating the resulting series.  That is M2-08.
- Network access.  That is M2-12.

*** Acceptance criteria

- [ ] Adaptation and validation are separate, independently testable
      stages.
- [ ] At least one legacy fixture reproduces bit-for-bit through the new
      path (the architecture's first replacement gate).
- [ ] Malformed rows fail with the row and reason, not a panic.
- [ ] No provider symbol is ever stored as instrument identity.

*** Legacy reference

=testdata/candles= and =datamanager/testdata_generator.go= supply the
fixtures.  =datamanager/dukascopy/= is the worked example of the
raw-file provider shape (including =IsValid='s local-file integrity
check) if a second adapter is wanted for contract-suite breadth.

*** Dependencies

M2-02, M2-05.

** M2-08 Implement canonical validation with explicit policies

*** Objective

Build the second normalization stage: validation of a canonical series,
with policies that make every repair visible.

*** Scope

- Checks: gaps, duplicates, ordering, session alignment against a
  =Calendar=, impossible prices, suspicious spikes, malformed volume,
  revisions.
- Policies: reject, drop, repair-with-a-quality-flag, or pass-and-record.
- A validation report enumerating every anomaly with its instrument,
  time, check, and applied policy.

*** Non-goals

- Silent repair.  A repair without a recorded quality flag is a defect.

*** Acceptance criteria

- [ ] Each check has a dedicated failing-input test.
- [ ] Every policy is exercised for every check class.
- [ ] Repairs are never hidden: the output record carries the flag and
      the report carries the reason.
- [ ] Session alignment is validated against =FXCalendar=, including a
      DST-transition week and a weekend boundary.
- [ ] Canonical bars can be cross-checked against preserved raw provider
      rows for the same range.

*** Legacy reference

=datamanager/data_validation.go= is the closest thing to a finished
donor in the whole survey: the request/issue/report triple, severity and
sample-missing reporting, =expectedOpenSlotCount=, and
=compareRawOandaMonth='s canonical-versus-raw diff.  Adopt the model;
drop the JSON tags, the =string= kind/severity fields (make them typed),
and the file-path-centric identity.  =market/forex_hours.go= supplies
real holiday data for =FXCalendarParams.Holidays=.

*** Dependencies

M2-02, M2-07.

** M2-09 Implement the canonical resampler

*** Objective

One canonical resampler deriving coarser intervals from finer canonical
data, aligned by =Calendar= rather than by elapsed duration.

*** Scope

- =M1= → =H1=/=H4=, and (within =FXCalendar='s single-day/single-week
  limit recorded in ADR-012) =H1= → =D1= and =D1= → =W1=.
- Incomplete trailing bars marked incomplete via =TimeRange.Elapsed=,
  never emitted as complete.
- Volume summation, OHLC aggregation, and gap behavior specified.
- Validation by comparing a derived interval against a provider's native
  bars for the same session calendar — the architecture document names
  this as the test that exposes boundary, holiday, and DST errors.

*** Non-goals

- Multi-day/multi-week grouping, which ADR-012 explicitly reports as an
  error rather than inventing a convention.  If M2 needs it, that is an
  ADR amendment, not a silent implementation.

*** Acceptance criteria

- [ ] Derived =H4=/=D1= bars match provider-native bars for one real
      fixture week, including a DST transition.
- [ ] Incomplete final bars are representable and marked.
- [ ] Gaps in source data produce gaps, not fabricated bars.
- [ ] One resampler; no per-adapter duplicate.
- [ ] A completeness threshold (how many source bars a derived bar
      requires) is explicit and configurable, not implicitly 100%.

*** Legacy reference

=datamanager/slot_boundaries.go= is the single highest-value donor in
the repository: =SlotBoundaries=, =SlotIndexForTime=,
=firstDailyBoundaryAtOrAfter=, =nextDailyBoundary=, and especially
=h4SlotsInDay=, whose comment records that it was verified against the
raw OANDA archive across 2005–2012 transition days — including the
fall-back day where the 1:00 local hour occurs twice.  =candle_agg.go=
supplies =aggregateWindow= and the =minValid= threshold.  Rewrite both
against =Calendar= instead of the hard-coded 17:00 America/New_York
constant, since ADR-012 already owns that rollover.

*** Dependencies

M2-02, M2-08.

** M2-10 Implement coverage and gap reporting

*** Objective

Answer "what data do we actually have, where are the holes, and how was
it derived" — the question that makes a reproducible backtest possible.

*** Scope

- =Coverage=: instrument, interval, first, last, gaps, sources,
  revision, warnings.
- =Gap= detection that distinguishes a *market-closed* interval from a
  *missing-data* interval by consulting the =Calendar=.  A weekend is
  not a gap.
- Coverage aggregation across multiple sources for one instrument.

*** Acceptance criteria

- [ ] A weekend, a session close, and a real hole are distinguished by
      test.
- [ ] Coverage reports the sources and revision that produced the data.
- [ ] Coverage is queryable through =HistoricalSource.Coverage=.

*** Legacy reference

=datamanager/candle_gap.go= — =BuildGapReport=, =classifyGap=, and the
=gapStats= shape (total/present/missing bars, gap count, weekend versus
suspicious counts, longest gap and its kind).  Generalize
=classifyGap='s weekday logic into a =Calendar= consultation so
holidays and early closes classify correctly too.
=datamanager/store_inventory.go= shows how coverage was scanned from
storage.

** M2-11 Implement the persistent file-backed store

*** Objective

Give the vertical slice durable storage, with the format hidden behind
the ports as the requirements document demands ("the user does not need
to know where the data came from or how it is stored").

*** Scope

- A CSV-backed store under =adapters/marketdata/csv=, implementing the
  same =Sink=/=HistoricalSource=/=CoverageCatalog= ports as M2-06.
- On-disk layout documented as an implementation detail, explicitly not
  a public contract, so Parquet can replace it later.
- Atomic writes, crash-safety behavior, and revision handling stated.

*** Non-goals

- Parquet.  Deferred until CSV is proven insufficient, per M2-01.
- Any query API that names a file, directory, or format.

*** Acceptance criteria

- [ ] Passes the identical contract suite the in-memory store passes.
- [ ] No caller outside the adapter can tell which format is in use.
- [ ] Interrupted writes leave no partially-valid file.

*** Legacy reference

* Proposed M2 Exit Criteria

M2 may close when all of the following hold:

- A single instrument's history can be acquired from a real provider,
  adapted, validated, stored, queried, and resampled through public APIs
  only, with no caller aware of the storage format.
- One trusted legacy fixture is reproduced through the new path.
- Coverage distinguishes market-closed intervals from missing data.
- A reproducible query can require =LocalOnly=/=ExactManifest= and fail
  rather than silently change its input set.
- Every repair is flagged; no silent data mutation exists.
- The contract suite passes for at least three adapters, one of them a
  real vendor.
- =tradertest= provides market-data builders and fakes, used by runnable
  CI examples.
- No broker, strategy, risk, or execution behavior has leaked into M2.
- =docs/plans/milestones.org= records the M2 breakdown and this document
  is superseded by it.

* Risks and Watch Items

1. *Scope creep through adjustment modes.*  Corporate actions, continuous
   futures, and total-return series are each large enough to consume M2
   alone.  M2-01 must defer them explicitly, and M2-04 must make the
   unsupported modes *fail loudly* so the deferral cannot be forgotten.
2. *Tick storage.*  The requirements document names real-time tick data,
   but M2's usable outcome is a historical vertical slice.  Defining
   =Quote=/=Trade= types now while deferring tick *storage* keeps M6
   additive without inflating M2.
3. *=marketdata.Trade= versus =order.Trade=.*  Appendix C flags this
   exact ambiguity.  Decide the naming in M2-02, not during review.
4. *The =Sink= public/internal question.*  Package-boundaries rule 12
   prefers =internal/= until a user needs it; the architecture document
   says =Sink= "may remain an internal extension point".  M2-05 should
   decide once rather than leaving it implicit.
5. *Legacy transplant discipline.*  ADR-013's sequence — contract test
   first, smallest useful copy, rewrite to new vocabulary, never import
   the legacy module — applies to every issue with a "Legacy reference"
   section, and most sharply to M2-09 and M2-11, where the legacy code
   is good enough to be tempting to paste wholesale.  The risk is not
   copying the *algorithms* (they are proven); it is copying the
   =string=-typed, globally-stateful *shape* around them, which would
   quietly undo ADR-002, ADR-003, ADR-004, and ADR-016 in a single
   milestone.
6. *DST correctness is the milestone's real difficulty.*  Two separate
   legacy bugs (#179's index-reconstructed timestamps, and fixed-stride
   D1/H4 aggregation) were both DST failures, and =h4SlotsInDay= needed
   verification against seven years of archive data.  M2-02 and M2-09
   should be scheduled with that in mind rather than estimated as
   ordinary type-definition work.
7. *Enforcement gap.*  Dependency-direction and API-diff tooling remains
   unbuilt (noted in both =package-boundaries.org= and the M1 review).
   M2 roughly doubles the package count; if that tooling is ever going
   to land, before M2's adapters multiply is the cheapest moment.
