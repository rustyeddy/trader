#+TITLE: ADR-092: Provider packages, the store and root-less data APIs
#+STARTUP: overview indent

* Status

Proposed. Records what the implementation of ADR-089, ADR-090 and ADR-091
(issues #634, #644, #639 and #647) changed in the package structure ADR-089
fixed, so the change is a decision on the record and not only a series of
edits. It amends parts of accepted ADR-089 and, once accepted, ADR-089 is to be
marked amended by it. Acceptance is the owner's decision (#643).

An honest note on process: the registry says an accepted ADR is superseded, not
edited. ADR-089's text was updated in place as the implementation landed
(package paths, the store, root-less APIs). Those edits are the implementation
state and are carried by this record; nothing in them changes the accepted
decisions about layout, the raw format or the S-1 secret rule.

* Context

ADR-089 placed OANDA's raw store and client in =internal/marketdata/oanda=, had
each package take the data root as an argument, and left file writing (atomic
replace, the per-partition lock) inside the packages that needed it. ADR-091
(Proposed) then set the direction: providers organized by external system, domain
services owning their rules, an application service layer coordinating them, and
the shared storage as its own concern. Three pieces of code wrote the same
temporary-file, sync and rename sequence and two held the same lock; three held
the same fixed-decimals price text rules.

* Decision

1. *Providers live under =provider/<name>=.* OANDA is =provider/oanda= (#634): the
   raw record, scope, reader, writer, inventory, REST client and credential, and
   the mapping of a raw partition to a =marketdata.SourcePartition=. A provider
   imports only public models and the foundational packages; it applies no domain
   rule. No package is created for a provider that does not exist.
2. *One package owns data-file I/O: =store= (#644).* It owns the data root
   (its default is =/srv/data=; =cmd/trader= sets another when one is
   configured, and tests set a temporary directory) and offers byte-oriented =Read=, =Write=,
   =Create=, =Update= and =List= on root-relative paths. Writes are atomic and hold
   a per-path lock; =Update= is the locked read-modify-write; =ErrUnchanged= lets a
   callback leave a file alone. It is format-agnostic. An architecture test forbids
   the provider and market-data packages calling standard-library file functions.
3. *Data APIs take no root.* =layout= builds paths relative to the root;
   =provider/oanda= and =canonical= functions lost their =root= parameter. The
   composition root (=cmd/trader=) is still the only place that resolves the root,
   in this order: =--data-root=, =TRADER_DATA_ROOT=, =marketdata.root= in the config
   file, then the store's default =/srv/data= (owner decision on #659, implemented
   in #660). The default is the store's alone: =cmd/trader= passes a root to the
   store only when one is configured.
4. *The market-data flow is three layers (ADR-091):* =cmd/trader= (transport) to
   =service/marketdata.go= (application service, one file) to =marketdata/service=
   (domain service) over =marketdata/internal/canonical=, with the provider mapping
   a raw partition into =marketdata.SourcePartition=. =Bar.Instrument= names a bar
   from its file's key and is never stored (#650).
5. *The text rules for fixed-width prices are =num='s* (=ParsePriceFixed=,
   =Price.FormatFixed=), shared by the scenario reader, the raw store and canonical.

* Consequences

- ADR-089's package list is out of date in the places above; this record is the
  current one. Its layout, raw-v1 format, immutability, lock semantics (process
  local) and secret rules stand.
- =download= still calls the provider from =cmd/trader= until it moves behind an
  application service (#641).
- The layout migration of an existing archive is =trader data migrate= (#642, below);
  a storage manager beyond the store is not built. The store's lock is
  process-local; two processes writing one file are not coordinated, which is why
  the migration must run with no download or build running.
- The canonical reader and the public series container (#647) will use the store
  through =marketdata/service=; nothing here constrains them.

* The migration (#642)

The archive on disk had =<root>/raw/<source>/...=; the code reads
=<root>/<source>/raw/...=. =trader data migrate= moves raw between the two, and only
raw: the old =canonical/= files are canonical-v1, which ADR-090 rebuilds from raw and
never reuses (they even share file names with canonical-v2 files, so moving them
would make every month read as stale and the first build overwrite them), so they are
listed and left for the owner to delete after a rebuild has passed =trader data
audit=.

- *A rename of each source's directory, not a copy.* On one filesystem it is one
  atomic =rename(2)=, as fast for 800,000 files as for one, and every file keeps its
  inode and bytes, so "byte-identical" holds by construction and is verified, not
  assumed. =store.Move= refuses to move onto anything that exists (rename would
  silently replace an empty directory), =store.Inventory= records path, size, time and
  inode, =layout.LegacyRawDir= owns the old-to-new mapping, and
  =service.MigrateLayout= plans, checks, moves and verifies. All file operations are
  the store's; the file-I/O architecture test now also covers =service= and
  =internal/marketdata=.
- *Dry run by default.* It moves nothing without =--apply=. It refuses, and moves
  nothing at all, if any destination exists, a source holds a symbolic link, or a
  store temporary file is found (a write in flight or interrupted); there is no
  merge and no overwrite.
- *Verified after every unit:* the same set of files with the same sizes,
  modification times and inodes; =--checksum= adds SHA-256 of every file before and
  after. A failure is reported and nothing is moved back automatically;
  =--reverse= moves everything back under the same checks. A rerun after an
  interruption moves what is left.
- *No fallback:* after the move the old place is not read (a test proves build does
  not see raw left in the old layout).

Every =raw/<source>= is moved, whatever its provider (dukascopy and stooq included):
a directory rename costs the same, and no code needs to read their files for it. The
migration is for the owner to run on =/srv/data=; tests use temporary directories
only. A read-only dry run on the real archive (2026-11-18) found 5 sources, 814,675
files, 28.4 GiB, in under two seconds, with no problems.

* Alternatives considered

- Leaving file I/O in each package: three copies of the atomic-write and lock code
  and no single place to change it.
- A =Storage= interface and a manager: rejected by ADR-091's rule against
  abstractions without a present need; the store is concrete.
- Keeping the root as an argument: it let one process name two roots and made every
  signature carry it; the process has one data root.
