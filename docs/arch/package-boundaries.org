* Supported External Surface

Top-level library packages are deliberate compatibility commitments. Trader's
runtime is under =internal/=; external strategies interact with it through
Strategy Protocol v1 and =sdk=. This replaces the earlier broad public
composition model (ADR-065, issue #400). There is no =pkg/= directory or
compatibility facade for removed import paths.

and =examples/sma-long-hold=, plus the separate-module acceptance fixture in

Independent external repositories were not inventoried by this change.

* Dependency Direction

#+BEGIN_EXAMPLE
external guest executable
    -> sdk -> protocol/strategy/v1
           -> public order, marketdata, instrument, num
    -> indicator
    -> analysis -> indicator, public marketdata/instrument

cmd/trader -> internal/service -> internal/backtest / internal/pipeline
internal/backtest -> internal/strategy, broker, journal, public values
internal/pipeline -> internal/execution, risk, broker
internal/marketdata -> public marketdata, instrument, num
                    -> internal/marketdata/internal/provider/*
internal/order -> public order, instrument, num, internal/id
#+END_EXAMPLE

Arrows mean imports. Public packages never depend on =internal/= runtime
packages. The package-private =num/internal/fixed= arithmetic implementation
is allowed, but its types must not appear in public signatures. No public
alias, constructor, method, field, or interface exposes runtime objects.

=sdk.Clock= contains only =Now() time.Time=. Protocol v1 carries host time,
not host-driven guest timers. SDK run/order/correlation IDs are opaque strings;
guest code does not generate canonical runtime IDs. Any future public SDK
fixture package must depend only on public contracts.

* Runtime Rules

1. Strategies emit intents and never submit broker orders.
2. Risk evaluates snapshots without calling brokers.
3. Execution and risk remain separate; pipeline owns their composition with broker submission.
4. Broker adapters translate external APIs without trading policy.
5. Service wrappers depend on their domain packages, never the reverse.
6. Concrete adapters are constructed at composition roots, not in services.
7. Reports consume results; trading behavior never depends on rendering.
8. Exact prices, quantities, money, and accounting values use =num=.
9. Time and identity are injected; no hidden global configuration or unmanaged goroutines.
10. Live-money operation requires explicit enablement and is never the default.
11. Dependencies remain acyclic. Move shared values to their semantic owner rather than adding interfaces to hide a cycle.
12. New public packages require a concrete consumer and an explicit compatibility decision.

* Enforcement

Go enforces external runtime import restrictions. =test/architecture=
builds a real guest in a temporary module with an unrelated import path, and
checks that direct imports of runtime packages fail specifically with Go's
internal visibility error. It checks the supported package inventory, each
public package's transitive dependencies, and exported type graphs for
internal types, including methods and aliases.

Existing package-level dependency checks continue to constrain runtime
layering. Configuration/logging/time checks retain their narrow composition
exemptions at the new paths. Normal verification is =make check= and
=make build=; optional data-dependent test suites are also compiled with their
build tags when moving their packages.

* Architectural References

ADR-065 owns this public boundary and its amendments to earlier public
composition promises. ADR-062/063 own protocol/process behavior; ADR-064 owns
the later Git-tag release process. The canonical architecture retains the
runtime responsibilities and invariants; CONTRIBUTING.org owns workflow and
review requirements.
