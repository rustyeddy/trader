#+TITLE: ADR-073: Stooq daily history is dividend-adjusted
#+STARTUP: overview indent

* Status

Accepted. Issue #464. Partial amendment of ADR-048 (see the Partial Amendment
Rules in =adr-decisions.org=); ADR-048 stays Accepted for everything else.
The code change this implies is issue #465.

* Context

ADR-048 decided that Stooq's daily equity bars are split-adjusted and so
record =AdjustmentSplitAdjusted=. It reached that from AAPL's two real
splits, and stated that dividend/total-return adjustment "was not separately
investigated" and "remains genuinely unverified and is not claimed either
way; if a future issue needs to know, it requires its own investigation (for
example checking price behavior around a known large ex-dividend date)".

The sub-decision amended here is the Stooq branch of ADR-048's Decision: "the
=stooq= branch returns =AdjustmentSplitAdjusted=, per the empirical finding
above", together with the Context sentence "Stooq's daily equity history is
therefore /split-adjusted/, not raw."

Two later pieces of work needed the answer: comparing Stooq with Alpaca
(=feed=iex=, split-adjusted only) for an out-of-sample holdout, and the
mismatch rule of ADR-072 (#459). Closes on the same trading days, Stooq
(=d_us_txt.zip=, downloaded 2026-09-10) against Alpaca:

closed at 271.60 on 2018-11-01 (Alpaca, matching the actual close) and
246.675 in all three Stooq copies on disk. Daily returns agree closely (SPY
mean absolute difference 0.03%); price levels do not.

* Decision

Stooq daily bars are back-adjusted for dividends as well as splits: a
total-return-style series. The adjustment convention recorded for provider
=stooq= is =AdjustmentTotalReturn=, the value ADR-048 reserved for exactly
this. Alpaca remains =AdjustmentSplitAdjusted=. Trader still only records the
convention a provider delivers (ADR-047, ADR-048); it does not compute or
select adjustments.

ADR-048's other decisions stand unchanged: the =AdjustmentPolicy= type,
recording it in =Manifest=, the identity wiring (=Revision= version tag and
=ConfigDigest=), the volume position, and the AAPL split evidence.

Changing the value in code is a separate issue (#465), implemented after
this ADR so the data-model change gets its own review.

* Consequences

- Stooq and Alpaca price levels are not comparable and must not be spliced
  into one series: the join would show a jump equal to the dividends paid
  since the join date. Keep them as separate provider-scoped datasets.
  Percentage returns, and indicators and stops defined on them, are
  effectively unaffected.
- Every ex-dividend date rewrites all older Stooq rows. A previously
  downloaded archive is therefore stale for level-based use after any
  ex-dividend date, and ADR-072's incremental import falls back to a full
  re-import in that case.
- Issue #465 records =AdjustmentTotalReturn= for Stooq through one function,
  =adjustmentPolicyFor=, shared by the build and by planning. A canonical
  partition whose stored policy differs from its provider's current one is
  reported stale (=Plan= schedules a rebuild, with the raw input unchanged),
  so datasets built before this ADR are relabelled on the next update
  instead of keeping a wrong label until someone forces a rebuild.
- No =manifestRevisionVersion= bump: the hashed encoding is unchanged, only
  the policy value for Stooq data is. Stooq datasets get a new =Revision=
  and =ConfigDigest= when rebuilt, which is the intended identity change.
  No checked-in fixture or golden contains a Stooq manifest.
- =TestStooqEndToEnd_AAPLRecordsSplitAdjustedPolicy= (named in ADR-048) is
  renamed =TestStooqEndToEnd_AAPLRecordsTotalReturnPolicy=; it still proves
  continuity across the AAPL split.
- Absolute-price rules (dollar thresholds, price-level screens) evaluated
  on Stooq history use adjusted, not historical traded, prices.

* Alternatives Considered

- *Leave ADR-048 unchanged and note the finding elsewhere.* Rejected: the
  recorded policy would stay wrong and the registry's rules forbid editing an
  Accepted ADR in place.
- *Supersede ADR-048 entirely.* Rejected: only one sub-decision changes; the
  type, identity wiring and volume decisions remain correct.
- *Change the policy value in the same step.* Rejected: it bumps
  =manifestRevisionVersion= and regenerates goldens, which deserves its own
  reviewable change (#465).
