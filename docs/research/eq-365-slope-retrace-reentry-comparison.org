#+TITLE: EQ-365: SMA-Slope and Percent-Retrace Re-Entry Comparison (SMA Long Hold)
#+STARTUP: overview indent

* Purpose

Issue #365 tests two re-entry-confirmation hypotheses for SMA Long
Hold, following #361's own inconclusive N-bar breakout finding
(issue #354's original diagnostic: the main structural weakness is
delayed re-entry after a defensive exit, most visibly the 1716-day
flat period reclaim-exit-price stays out of the market after its own
2007-12-27 exit, missing the entire 2009 recovery until 2012):

- *Hypothesis A (SMA slope)*: require the long-term regime itself —
  the SMA's own trajectory, not merely price relative to it — to have
  turned upward before re-entering.
- *Hypothesis B (percent retrace)*: require a fixed fraction of
  recovery from the post-exit low before re-entering.

Both are compared against the playbook's current reference re-entry
rule (=reclaim-exit-price=), using full backtest results with real
fills and state (never a trigger-date-only analysis, issue #365's own
explicit guardrail).

*Revision note*: PR #372's review (Rusty + Copilot) found a real
correctness bug in =percentRetraceReEntryRule=, a stale-provenance gap
in the research request, and two reporting-precision issues; all are
fixed, and the results below reflect the corrected numbers — see "What
Changed After Review."

* New Strategy Code

=strategy/smatrend/reentryrule.go= gained two new =ReEntryRule=
implementations, registered under four fixed names — no configurable
=Config= surface, matching =breakout-2=/=breakout-3='s own precedent
(issue #365's own guardrail against a broader sweep):

- =smaSlopeReEntryRule= ("above-sma-slope-20", "above-sma-slope-50"):
  =SMA(today) > SMA(N bars ago)=, on top of the existing central
  above-SMA gate every =ReEntryRule= already relies on.
- =percentRetraceReEntryRule= ("retrace-25", "retrace-50"): tracks
  the lowest Low observed since the exit — including the *current*
  bar's own Low, not only prior bars' (see "What Changed After
  Review") — resetting the recovery threshold from any new, lower
  low, and re-enters once Close has recovered 25%/50% of the decline
  from the exit price down to that low. Computed additively
  (=low + fraction*selloff=) rather than via a division, so a
  near-zero selloff can never divide by zero; if no decline below the
  exit price ever occurred, there is nothing to recover from and the
  rule enters unconditionally once the central gate passes.

=ReEntryRule= gained a new optional capability, =SMAObserver=
(=ObserveSMA(smaValue float64)=): =smaSlopeReEntryRule='s own trigger
depends on the SMA's continuous trajectory regardless of position
side, which the existing =ObserveFlatBar= (flat-only) cannot supply —
a slope computed only from flat-bar samples would silently skip every
bar spent Long, understating how long the SMA has actually been
moving in one direction. =Strategy.OnBar= now calls =ObserveSMA=
unconditionally on every ready bar, before the Flat/Long dispatch,
mirroring how =crossState= is already maintained continuously. A new
integration test,
=TestStrategy_SMASlopeReEntryObservesSMAContinuouslyNotJustWhileFlat=,
proves this wiring the same way issue #361's own
=TestStrategy_BreakoutNReEntryObservesBelowSMABarsNotJustAboveSMAOnes=
proved =ObserveFlatBar='s wiring — confirmed meaningful by moving the
call into the Flat-only branch and observing the test fail before
restoring it.

=smatrend.Version= is bumped to ="v3"= (PR #372 review): four new
stateful entry behaviors plus unconditional SMA observation are new
control flow for every configuration, not only ones naming the four
new rules — a =v2= manifest and a =v3= manifest are not directly
comparable.

Exit behavior is completely unchanged.

* Primary Comparison Now Uses Reference-Price-Exact Full-Notional Sizing Directly

Issue #364 (=risk.NewFullNotionalSizer=, ADR-061) landed before this
issue's own research phase, and materially simplifies the protocol
#361 had to use: =backtest.resolverInputBuilder= already sets
=pipeline.Input.ReferencePrice= to =event.Bar.Open= on *every*
submission (issue #216, M5-08 review) — the real bar-open price at
the actual moment of each entry, not a fold-anchored approximation.
Swapping in =risk.NewFullNotionalSizer()= therefore sizes every entry
exactly at 100% of available capital *at that reference price*,
continuously, with *no walk-forward folding needed at all* — the
entire reason #361's own walk-forward protocol existed in the first
place. The primary comparison below is one single continuous backtest
per variant, not a chained walk-forward.

*Reference-price-exact, not fill-price-exact* (ADR-061's own explicit
boundary; PR #372 review caught this report's first draft overstating
it): the simulated broker's own Buy fill is rounded up to the
listing's own tick size, which can differ from the unrounded
=ReferencePrice= the =Sizer= computed the quantity from. Every number
below is therefore exact at the supplied reference price, not a
guarantee of exact notional at the real, tick-rounded fill.

* Method

Two runs, both holding =ExitRuleName= "probation-trend",
=InitialStopBelowSMA= 0.01, =TrailActivationGain= 0.05,
=TrailingStopPercent= 0.10 fixed; only =ReEntryRuleName= varies across
=reclaim-exit-price=, =above-sma-slope-20=, =above-sma-slope-50=,
=retrace-25=, =retrace-50=. Each run's own =svcbacktest.RunRequest.
StrategyParameters= now carries the effective =smatrend.Config= (PR
#372 review), so each variant's own manifest/config digest is
distinguishable rather than all five sharing one digest despite
=ReEntryRuleName= differing.

** Primary: one continuous run per variant, reference-price-exact full-notional sizing

=risk.NewFullNotionalSizer()=, sized against real bar-open reference
prices throughout, over SPY's full Stooq history (2005-02-25 through
2026-09-04). A buy-and-hold benchmark row, computed directly from
Close prices (exactly 100% invested by construction, no =Sizer=
involved), covers the identical span.

** Secondary (diagnostic): one continuous run per variant, reference (1%-risk) sizing

The playbook's own established reference sizing (=RiskFraction= 0.01,
fixed $20 adverse distance) — useful for the whipsaw/named-episode
analysis, which is sizing-independent; its absolute CAGR/return must
not be read as a portfolio-allocation answer.

Full reproduction:
=marketdata/smatrend_slope_retrace_reentry_fullarchive_test.go=
(=TestSMATrendSlopeRetraceReEntryComparison= and
=TestSMATrendSlopeRetraceReEntryDiagnostic=; build tag =fullarchive=;
local path constants edited locally, never committed).

differs from the SMA-slope variants and baseline (2022-04-11) — a

before baseline's own April exit, exactly the "changing re-entry
timing cascades forward through the whole trade sequence" effect
#361's own report documented; not a labeling artifact.

* What Changed After Review

PR #372's review found a real strategy-correctness bug and three
provenance/precision issues in the first version of this PR; all are
fixed and the numbers above reflect the correction.

** =percentRetraceReEntryRule= excluded the current bar's own Low

The first implementation's =ShouldEnter= compared only against
=postExitLow= as of *prior* bars, following =nBarBreakoutReEntryRule='s
own check-before-update ordering — correct for a breakout rule (whose
threshold is a fixed prior level a bar's own High must exceed), but
wrong for a retrace rule: the hypothesis is explicitly defined as "the
lowest Low observed since exit," and a bar that itself sets a new,
lower low is part of that history the moment it happens, not one bar
later. On a bar that both sets a new low *and* closes above the
recovery threshold that new low implies, the old code incorrectly
compared against the stale, higher prior low and could report no entry
when the corrected code (comparing against
=min(prior postExitLow, this bar's own Low)=, still never mutating
state outside =ObserveFlatBar=) correctly enters on that same bar. A
new regression,
=TestPercentRetraceReEntryRule_ShouldEnterUsesThisBarsOwnNewLowerLow=,
covers exactly this case — confirmed meaningful by reverting to the
old stale-low-only comparison and observing the test fail.

This changed the retrace-25/retrace-50 numbers materially (both the
primary full-notional table and the diagnostic/episode tables above
reflect the corrected rule); the SMA-slope numbers are unaffected
(unrelated rule).

** Provenance and precision fixes

- =smatrend.Version= bumped from =v2= to =v3= (the new stateful
  entry behaviors are new control flow for every configuration).
- =StrategyParameters= is now populated in the primary run's own
  =RunRequest= with the effective =smatrend.Config=, so each variant's
  manifest/config digest is distinguishable.
- "Exact full-notional" was corrected to "reference-price-exact" —
  ADR-061's own explicit boundary is exactness at the supplied
  reference price, not a promise about the real, tick-rounded fill.
- The report's first draft claimed both retrace variants were "ahead
  of baseline on every metric" — untrue for =retrace-25=, whose own
  max drawdown is worse than baseline's; the Results/Analysis/
  Conclusion sections below are corrected to distinguish =retrace-25=
  from =retrace-50= rather than treating them identically.
- Named-episode diagnostics now include the post-exit low, its date,
  and the hypothesis-aligned recovery fraction at re-entry (the
  previously-reported =ReboundBeforeReEntryPct= is a different metric,
  =(reentryPrice-low)/low=, and cannot verify where a 25%/50%
  threshold actually fired).

* Analysis

Three of the four candidates (both SMA-slope variants and
=retrace-50=) produce a materially different result from #361's own N-
bar breakout finding: where breakout-2/breakout-3 bought a small CAGR
gain at a real, larger Calmar cost, these three improve *both* metrics
simultaneously against the identical baseline and exit rule. The
named-episode evidence explains why: both mechanisms directly target
the exact failure mode #354 first identified (a defensive exit that
then misses a large, obvious recovery) rather than merely reacting
faster to short-term price action the way a bare N-bar breakout does —
an SMA slope confirms the *regime* has turned, and a percent retrace
confirms *meaningful* recovery has actually happened, both of which
correlate better with "the rally is real" than "the last 2-3 closes
ticked up."

=retrace-25= is the one candidate that does not clear this same bar:
its own CAGR gain is the largest of the four, but it comes with a
genuinely larger drawdown than baseline, not merely a smaller Calmar
improvement — a real cost, not only a weaker benefit. This is a
meaningful, not marginal, distinction between the two retrace
thresholds: a shallower confirmation requirement (25%) re-enters
sooner, catching more of the recovery but also re-entering into more
of what turns out to be continued chop, while the deeper confirmation
(50%) waits for more of the recovery to already be underway,
producing the single best combined risk profile of any candidate here.

Between the SMA-slope candidates and =retrace-50=, no single variant
dominates every metric: =above-sma-slope-20= retains slightly less
buy-and-hold CAGR than =retrace-25= (and less than =retrace-50=
retains relative to its own drawdown-adjusted profile), while
=retrace-50= achieves the best combined risk profile outright. This
evidence does not by itself distinguish which specific mechanism (or
threshold) is preferable — only that three of the four tested
configurations are genuine improvements over =reclaim-exit-price= on
this dataset, and one (=retrace-25=) is a real but more costly
improvement, not a clean one.

* Conclusion

*Hypothesis A (SMA slope): PROMISING.*

Both =above-sma-slope-20= and =above-sma-slope-50= improve CAGR (+18-
21% relative), Calmar (+14-18% relative), and dramatically shorten both
named long-flat episodes (2008: 1716 -> 596-628 days; 2022: 428 -> 333-
366 days) relative to baseline, while whipsaw rate stays flat or
slightly improves. This clears the bar #361's own breakout candidates
could not: a genuine improvement, not a marginal return gain funded by
materially more drawdown.

*Hypothesis B (percent retrace): PROMISING, with the two thresholds
genuinely distinguishable.*

=retrace-50= improves CAGR (+18% relative) *and* reduces max drawdown
(-0.69 points) *and* improves Calmar (+22% relative) relative to
baseline simultaneously — the strongest single combined result in this
entire comparison family across #361 and #365. =retrace-25= improves
CAGR more (+22% relative) but at a real drawdown cost (+1.71 points)
that its own Calmar improvement (+13% relative) only partially
compensates for — still ahead of baseline, but a genuinely different,
more costly trade-off than =retrace-50=, not simply a smaller version
of the same result. Unlike the SMA-slope pair (whose two lookbacks
produced closely comparable outcomes), the two retrace thresholds
diverge enough that this comparison itself recommends the deeper
(50%) confirmation over the shallower (25%) one, rather than leaving
the choice open.

Per issue #365's own guardrail, this is not a substitute for broader
out-of-sample validation, and multiple candidates clearing the bar on
one dataset warrants some caution before treating either hypothesis as
settled — but both hypotheses earn further consideration, unlike
#361's own breakout candidates. The natural next step is validating
whether this holds out-of-sample (a different instrument, or a genuine
train/test split) before promoting any candidate to the playbook's own
new reference re-entry rule — tracked as a follow-up, not attempted in
this issue per its own scope (no broader parameter sweep, no holdout
tuning).

The selloff-severity-dependent threshold idea issue #365 itself named
as a possible follow-up (vary required recovery with selloff severity)
is not pursued here, per that same issue's own explicit deferral —
this fixed-threshold result (particularly the real divergence between
=retrace-25= and =retrace-50=) is promising enough to make that
follow-up worth considering, but it should be its own issue, earned by
this data rather than pre-optimized ahead of it.
