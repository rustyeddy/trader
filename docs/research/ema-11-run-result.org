#+TITLE: EMA-11: First EMA Crossover Research Experiment Result
#+STARTUP: overview indent

* Purpose

This document records the first real historical run of the EMA
crossover strategy (issue #256, EMA-11) against the reference
configuration =docs/research/ema-01-experiment-definition.org=
(EMA-01) specified, and states an explicit research conclusion. It is
a results record, not a durable architecture decision — it carries no
ADR number (see =docs/arch/adr-decisions.org=).

Trader's own CLI (=trader backtest run --config=) produced this run
end to end, through the real =service/backtest=/=backtest.Runner=/M4
pipeline/simulator path (the same path EMA-05 through EMA-10 already
proved deterministic and correct at the unit/regression level) — no
special research-only code path exists or was added for this
experiment. The one code change this issue did add,
=cmd/trader/backtest= gaining an optional =--journal= flag, is pure
CLI plumbing (an opt-in destination for an already-existing journal
capability); it does not touch strategy, execution, risk, or simulator
behavior.

** Config

rest of =research-runs/=; reproduced verbatim below since it is small
and this document is the durable reference for it):

backtest:
  symbol: EURUSD
  interval: H1

  to: 2025-01-01T00:00:00Z

#+END_SRC

Every value matches EMA-01's Decisions 5 and 7 exactly: 10,000 USD
starting capital, 1% fixed-fraction risk, 0.0050 adverse distance
(sizing input, not a broker-side stop — EMA-01 Decision 5), and the
half-open =[2015-01-01, 2025-01-01)= range (last calendar day included
is 2024-12-31).

** Command

#+BEGIN_SRC sh
trader backtest run \
  --config research-runs/ema-11/ema01-reference.yaml \
  --data-raw-root /srv/trading/data/raw/oanda \
  --data-store-root <fresh-directory> \
  --output-dir research-runs/ema-11/runs \
  --journal research-runs/ema-11/run.jsonl \
  --format json
#+END_SRC

=--data-raw-root= points at the real OANDA raw archive
(=PAIR-YYYY-MM-<tf>.csv= partitions; see
=marketdata/internal/provider/oanda/doc.go='s own "Archive shape"
section for the exact layout and schema this run's raw source
follows).
=--data-store-root= should be a fresh directory: the canonical EUR/USD
H1 store is rebuilt from raw on every run of this exact command
regardless, so a stale store only wastes disk, it never changes the
result (canonical data is content-addressed by revision — see below).

** Determinism check performed

Two independent runs of the exact command above (one before, one after
the =--journal= commit landed — the second is the officially recorded
run below) produced *byte-identical* trade/account/performance figures:
identical 1175 trade count, identical -1510.02803 USD net PnL,
identical final equity, identical win/loss/side breakdowns. The two
runs' =ConfigDigest= values differ (~77728a8...~ vs ~b9a5c2f...~) —
this is =backtest.Manifest.ConfigDigest='s already-documented,
already-known gap (ADR-042's own finding: each dataset's =BuiltAt=
wall-clock timestamp is embedded in the digest), not a reproducibility
failure of the actual trading result. Every trading-relevant field
reproduced exactly; only the incidental build-timestamp-derived digest
differed, exactly as ADR-042 already predicts for any two independent
canonical-store builds.

** Anomalies discovered while reviewing trades

- *Worst single trade*: -536.31084 USD, a long opened 2016-06-22T20:00Z
  and closed 2016-06-24T03:00Z — the Brexit referendum result (declared
  the morning of 2016-06-24 UTC). This is a real, known historical
  volatility event coinciding exactly with the worst trade in the
  entire 10-year run, not a data or simulation defect; it is recorded
  here specifically so a future reviewer does not mistake it for a bug
  and re-investigate it.
- *Best single trade*: +1,115.5807 USD, a short held 2015-02-26 through
  2015-03-17 (roughly 19 days) — the early-2015 dollar-strength/EUR
  weakness trend, also a known historical period, not an anomaly.
- *Trade duration spread is wide*: minimum 1 hour, maximum 502 hours
  (~21 days), median 45 hours, mean ~74.4 hours. 54 of 1175 trades
  (4.6%) closed within the very next bar after opening (a same-session
  whipsaw reversal) — expected from a crossover strategy with no
  minimum-hold or noise filter, not itself evidence of a defect, but a
  concrete number worth carrying into any follow-on experiment that
  adds a noise/whipsaw filter.
- *Year-by-year PnL is highly uneven*: 2020 alone contributed +2,977.08
  USD (the single best year, in a year of unusually strong, sustained
  FX trends during the COVID volatility regime); 2016, 2017, 2021, and
  2024 were the worst years (-1,846.59, -1,254.36, -1,196.49, and
  -1,800.53 USD respectively). No single year's result is required to
  explain the aggregate — the aggregate is genuinely a 10-year sum, not
  dominated by one outlier year — but the concentration of the one
  clearly good year (2020) alongside four clearly bad years is worth
  carrying forward: a regime-dependent crossover edge (trending vs.
  ranging markets) is a plausible next hypothesis, consistent with the
  =project_regime_filter_design= work already scoped in a prior legacy
  system.
- No data-integrity anomaly (out-of-order bars, gaps, duplicate
  fills, or a =KindSignal=/=KindFill=/=KindTrade= count mismatch) was
  found while reviewing the journal, and the counts reconcile exactly:
  1176 =KindSignal= records (one per detected crossover, EMA-08's own
  cadence — never one per bar) against 2351 =KindFill= records solves
  to exactly one flat->direction signal (a single Enter fill) and
  1175 reversal signals (an Exit + Enter fill pair each): 1 + 1175 =
  1176 signals, 1x1 + 1175x2 = 2351 fills, both exact. This is the
  expected shape given EMA-01 Decision 4: only the very first
  crossover of the entire run can find the strategy flat: every
  crossover after that finds it already long or short (it never exits
  without immediately reversing), so 1175 of the 1176 signals are
  necessarily reversals. 1175 closed trades + 1 still-open trade at
  the end of the range also reconciles with 1176 total positions
  opened across the run.

* Research Conclusion

*Rejected — move to next experiment.*

The reference hypothesis (docs/research/ema-01-experiment-definition.org's
own framing: "A fast EMA crossing a slow EMA identifies trend changes
that, when traded long/short with opposite-cross exits, may produce
positive expectancy on EUR/USD H1") is not supported by this run.
Every headline metric points the same direction: negative net PnL
(-1,510.03 USD, -14.54% return over 10 years), a profit factor below
1.0 (0.971), negative per-trade expectancy (-1.29 USD), and a 43.09%
maximum drawdown — a drawdown of that magnitude would be operationally
unacceptable even if the sign of expectancy were reversed. This
conclusion concerns the crossover entry/exit hypothesis and this
specific fixed, simplified sizing/cost model together (EMA-01 Decision
5's own explicit caveat) — it is not a statement that the
implementation is incorrect. The implementation's correctness is
judged separately, by the deterministic unit/regression tests EMA-03
through EMA-10 already established and which this run's own
determinism check (above) reconfirms at full scale.

** Obvious next experiment

Two follow-on directions are both directly motivated by this result,
in order of how directly they attack what the anomaly review above
found:

1. *Add a realistic cost model.* EMA-01 Decision 6's zero-cost
   idealization is a known, stated simplification; a fixed spread
   and/or commission model (already an explicit "expected follow-on"
   per that decision) can only make this specific negative result
   worse, not better, since 1175 trades at any nonzero per-trade cost
   subtracts further from an already-negative net PnL. This is worth
   running once, briefly, specifically to confirm the rejection is not
   an artifact of an unrealistically generous zero-cost assumption
   understating how bad a live version would be — not because it could
   plausibly flip the conclusion to Promising.
2. *Introduce a regime or trend-strength filter before trusting a
   crossover signal* — motivated directly by the year-by-year anomaly
   above (one strongly trending year, several weak/ranging years) and
   by the 4.6% same-bar whipsaw-reversal rate. A crossover signal
   filtered by a volatility/regime gate (for example, only trading
   crossovers when a longer-window trend-strength or ATR-percentile
   measure exceeds a threshold) is the most direct hypothesis this
   specific evidence supports, and is a smaller, cheaper change to test
   than redesigning the entry/exit logic itself.

Both are new experiments, not a revision of this one: per EMA-01's own
framing, this document's role is to record this hypothesis's result
and conclusion, not to iterate on it in place.
