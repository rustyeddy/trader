#+TITLE: Independent AI-Assisted PR Review Rubric
#+STARTUP: showall

A short, vendor-neutral rubric for one assistant (Claude Code, Copilot,
ChatGPT, ...) reviewing another assistant's pull request.  It supports the
Reviewer role in =docs/workflows/ai-development.org=.  The reviewer *never
approves or merges*: the maintainer keeps the merge decision.

* Inputs

Work only from:

1. The PR diff (=gh pr diff N=) and the linked issue with its acceptance
   criteria.
2. The ADRs and architecture sections the change touches (selectively, per
   =AGENTS.md=), plus =docs/arch/package-boundaries.org= when imports or
   public APIs change.
3. Test evidence: the PR's stated commands and results, CI status, and, where
   practical, your own run of =make check= on the PR head.

Do not rely on the author's reasoning or chat history.

* Rules of evidence

- *Verify or say you could not.*  A claim you did not check is reported as
  "not verified", never as confirmed.  Do not invent test runs, line numbers,
  or ADR text.
- *Name what is missing.*  If the PR claims "tests pass" with no command, no
  CI link, or no coverage of an acceptance criterion, record that as missing
  evidence.
- Cite the source of every finding: =file:line=, an ADR number, an issue
  acceptance criterion, a PR description or comment, or a CI/check run.  Use
  whichever applies; evidence findings usually cite the PR description or
  checks rather than code.
- State which commit you reviewed.

* Finding labels

Every comment carries exactly one label:

- *Blocker*: must be fixed before merge (wrong behavior, unmet acceptance
  criterion, ADR/boundary violation, safety or determinism risk, missing
  evidence for a stated requirement).
- *Suggestion*: improvement the author may take or decline with a reason.
- *Question*: something you could not determine; the author answers with
  evidence.

* Checklist

#+BEGIN_EXAMPLE
## Review of #<n> @ <sha>
Reviewer: <assistant>; inputs read: <diff, issue, ADRs <numbers>, CI run>

- [ ] Acceptance criteria: each criterion met, with evidence (test/line)
- [ ] ADRs and package boundaries: no contradiction; new import directions OK
- [ ] Correctness and edge cases: empty/zero/error/boundary inputs, error
      handling, resource closing
- [ ] Regression coverage: tests fail without the change; error and boundary
      paths covered
- [ ] Concurrency: ownership, shared state, goroutine/process lifetime, -race
- [ ] Trading invariants (mark N/A with a reason when not touched):
  - [ ] No look-ahead: decisions use only data available at the bar's time
  - [ ] Spread, commission and slippage/cost handling is explicit and unchanged
        or justified
  - [ ] Reproducible: same inputs give the same outputs (clock, randomness,
        map order, floating-point rounding)
  - [ ] Risk and sizing controls are not bypassed; strategies emit intents,
        not broker orders
  - [ ] Paper trading remains the default; no credentials or secrets
        in code, config files, flags, logs or errors; every credential
        config field is tagged =secret:"true"= (ADR-078 S-1)
- [ ] Evidence: commands/exit statuses stated; anything not run is disclosed
- [ ] Docs: updated where behavior, boundaries or ADRs changed

### Findings
- Blocker: <file:line> — <issue> — <suggested fix>
- Suggestion: ...
- Question: ...

### Not verified
- <what you could not check, and why>

Recommendation: <findings only; the maintainer decides to merge>
#+END_EXAMPLE

* Pilot: PR #490

PR #490 ("feat(backtest): study summary instead of a trade report for model
runs", issue #489) was written by Claude Code and independently reviewed by
Copilot, a different assistant, before the maintainer merged it (merge
=b666335=).  That real review is the pilot.  Reviewed commit: =eec465a=; final
head: =143aa59=.

** Copilot's findings, in rubric terms

Copilot worked from the diff and the repository, not from the author's
reasoning.  Copilot did not use these labels; they were assigned afterwards to
show how its four findings map onto the rubric:

| Label   | Source                      | Finding                                            | Author response (head 143aa59)                      |
|---------+-----------------------------+----------------------------------------------------+-----------------------------------------------------|
| Blocker | =study.go= (span rendering) | Dates dropped the hour/minute accepted by =from/to= | Span now RFC3339; tested                            |
| Blocker | =study.go= (writes)         | =fmt.Fprintf= errors discarded: truncated output   | One =io.WriteString=, error returned; tested         |
| Blocker | =run.go:290= (model branch) | No test executes the new branch                    | CLI-level tests against a fixture; fail with branch off |
| Suggestion | =study.go= (org format)  | =--format org= aliased the table                   | Dedicated Org shape; tested                          |

All four were actionable, cited a location, and were resolved with a reply and
a test.  The maintainer merged after the fixes.

** Evidence recorded for #490

- Head =143aa59=; CI check =ci= on that commit: success (run 37977124335,
  workflow run #795).
- PR comment from the author: "=make check= and =make lint= pass locally."
  This is the author's own statement; the commands' output is not quoted.
- Missing evidence (Question): the description says the change was "verified
  against the real forex-atr scanner (21 pairs, 2020-2024)" but gives no
  command or output.

** What a rubric-guided pass adds

Applying the full checklist to the same diff (by the authoring assistant, so
*not independent*; treat as candidate follow-ups for a human or a different
assistant to confirm) turned up items Copilot's pass did not raise:

- Concurrency (verified, not assumed): =signalCounter.signals= is an
  unsynchronized integer.  =internal/backtest/scheduler.go= and =runner.go=
  contain no goroutines or =sync= use, and the existing
  =internal/backtest/journal_counter.go= (=countingRecorder.count=) counts
  records the same unsynchronized way on the same =Record= path.  So the
  counter relies on the host serializing =Record= calls, as the existing code
  does.  This was established by search, not by running =-race= on a study.
- Suggestion: =--format= is validated only after the run completes
  (=run.go:316=, =study.go:101=), so a typo wastes a long study.  The same
  holds for backtest runs.
- Suggestion: a run with zero signals and no journal prints "0 (not kept; pass
  --journal PATH to keep them)" (=study.go= =signalsNote=).
- Question: =signalCounter= duplicates the counting-wrapper pattern of
  =countingRecorder=.  Could one be shared?
- Trading invariants: N/A.  Output formatting only; no data access, costs,
  sizing, or orders changed; paper-trading default untouched.

** Lessons for the rubric

- An independent assistant caught three blockers that the author's own tests
  missed, which is the point of the separate Reviewer role.
- Review claims need a source: findings citing a PR comment or a check run
  (as above) are as valid as findings citing code, hence the broadened
  citation rule.
- A self-review is useful for filling checklist items the independent pass
  skipped, but must be labeled as non-independent and not replace it.
