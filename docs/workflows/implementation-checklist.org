#+TITLE: Issue Implementation Checklist
#+STARTUP: showall

A short, provider-neutral checklist for implementing an issue.  Any
contributor, human or assistant, copies it into the issue (as a plan comment)
or the PR description and fills it in.  It needs only GitHub and the commands
in the =Makefile=; it complements, and does not replace, the issue and PR
templates in =.github/= and the workflow in =docs/workflows/ai-development.org=.

* How to use it

1. Copy the checklist below into a comment on the issue before substantial
   work, then keep it current as the work proceeds.
2. Fill every field.  Write "None" or "N/A: <reason>" rather than leaving a
   field empty.
3. Tick a box only when the evidence next to it exists.  "Tests pass" is not
   evidence; the command and its result are.
4. Carry the final state into the PR description (the PR template has matching
   sections) and into the handoff comment.

* Evidence rules

- Quote the exact command you ran and the relevant result line, e.g.
  =make check: ok= with the package summary, not "tests pass".
- If you did not run something, say so and why.  Unverified claims are
  recorded as unverified, never as passing.
- Link or name files, ADR numbers, and commit SHAs rather than describing
  them from memory.
- A tick without evidence is treated as unticked by the reviewer.

* Worked example: issue #492

Applied after the fact to #492 ("AI dev: Document multi-assistant issue-to-PR
handoffs"), whose scope is unchanged by this example.

## Implementation checklist — #492

### Scope
- Issue goal: document how Claude Code, Copilot and ChatGPT hand work to each other.
- In scope: docs/workflows/ai-development.org; links from contributor docs.
- Out of scope: any automated orchestration; code changes.
- Scope changes: None. (A review asked to mark an older pipeline plan as
  exploratory; that was a wording fix to keep the docs consistent.)

### Context consulted
- Packages and tests inspected: none (docs only).
- ADRs / architecture sections read: none needed; AGENTS.md and
  CONTRIBUTING.org for process.
- Package-boundary impact: None.

### Acceptance criteria
- [x] End-to-end issue -> implementation -> review -> merge example
      — evidence: "Example: issue to merge" in ai-development.org
- [x] Handoff template with SHA, files, tests, risks
      — evidence: "Handoff template" in ai-development.org
- [x] Reads only issue-relevant ADRs, per #491
      — evidence: "Principles" in ai-development.org
- [x] No simultaneous edits; no vendor lock-in
      — evidence: "Roles" rules in ai-development.org
- [x] Linked from contributor docs
      — evidence: CONTRIBUTING.org, AGENTS.md, README.md

### Tests
- [ ] Tests added/updated: N/A: documentation only, no behavior changed
- [ ] Commands run and results: `make check` not run locally (docs only).
      CI check `ci` on PR #498 head 3f5f65b: pass (run 38193275151, #801).
- [ ] Race detector: N/A: no Go code or concurrency touched
- [ ] Lint: N/A: no Go code changed (`make lint` not run)

### Documentation

### Safety

- [x] Determinism unaffected

### Design escalation
- [x] Architecture settled; needs-design not required.

### Risks and handoff
- Open risks: the older automated-pipeline plan could be mistaken for policy;
  mitigated by a header marking it exploratory.
- Branch @ commit: docs/492-ai-handoffs @ 3f5f65b; merged to main as cbeffde.
- Changed files: the five docs listed above, plus the new
  docs/workflows/ai-development.org.
- Next step / who: none; merged and the branch deleted.
